# Спецификация: сдача с передачей места боту

## Цель

Игрок может необратимо сдаться, после чего его место немедленно принимает бот.
Партия продолжает обычный игровой цикл без ручных действий сдавшегося игрока,
а результат отличает корректную сдачу от молчаливого лива.

## Термины

- **Completed** — игрок продолжал играть сам до конца партии.
- **Surrendered** — игрок явно подтвердил сдачу, после чего его место доигрывает бот; это не leave.
- **Abandoned** — игрок перестал участвовать без подтвержденной сдачи; в статистике это leave.
- **Outcome group** — группа результата для ранжирования: `completed`, затем `surrendered`, затем `abandoned`.

## Пользовательские сценарии

### Сценарий 1: явная сдача

Игрок во время своего действия выбирает Surrender и подтверждает необратимость.
Система передает его место боту, сохраняет результат `surrendered` и больше не
ждет от человека ни обычных действий, ни обязательных выборов вроде World
Government Terraforming.

### Сценарий 2: отказ от подтверждения

Игрок открывает подтверждение Surrender, но выбирает Continue. Партия,
очередность, счетчики действий и управление местом остаются без изменений.

### Сценарий 3: ошибка запуска бота

Если бот не может быть запущен, сдача не фиксируется частично: игрок сохраняет
управление, получает понятную ошибку и может повторить действие позже.

### Сценарий 4: рейтинг с ливнувшим игроком

В трехместной партии оставшийся игрок получает первое место, корректно
сдавшийся — второе, а подтвержденный молчаливый лив — третье. Внутри одной
outcome group порядок определяется итоговыми VP, затем MC.

### Сценарий 5: рестарт сервера

После рестарта активной партии сохраненная сдача остается в состоянии игры, а
бот за это место возобновляется до выдачи следующего обязательного выбора.

## Функциональные требования

| ID | Требование | Статус |
| --- | --- | --- |
| FR-001 | Surrender остается действием конкретного игрока и требует явного необратимого подтверждения. | Принято |
| FR-002 | Подтвержденный Surrender передает то же место боту и прекращает человеческое управление этим местом. | Принято |
| FR-003 | Переход `human → surrendered bot` атомарен с точки зрения пользователя: ошибка запуска или сохранения не оставляет частично сданное место. | Принято |
| FR-004 | Сдавшееся место продолжает все игровые фазы и обязательные prompts через бота, включая World Government Terraforming. | Принято |
| FR-005 | Surrender сам по себе не завершает multiplayer game и не исключает место из обычного игрового цикла; игра заканчивается по штатным условиям. | Принято |
| FR-006 | Состояние Surrender переживает сохранение и рестарт, после чего бот автоматически возобновляется. | Принято |
| FR-007 | В completion reliability Surrender не считается leave; Abandoned считается leave. | Принято |
| FR-008 | Рейтинг упорядочивает outcome groups как `completed > surrendered > abandoned`, а внутри группы использует VP и затем MC. | Принято |
| FR-009 | Игрок, созданный как автоматический участник, не может нажать Surrender; такая игра сохраняет существующие правила исключения из ELO. | Принято |
| FR-010 | Управлять Surrender может только владелец конкретной player-ссылки или защищенный администратор; shared game capability не дает доступ к чужому месту. | Принято |
| FR-011 | Сервер пишет санитизированные события о принятой/отклоненной сдаче и запуске/восстановлении бота без секретов и приватной игровой информации. | Принято |
| FR-012 | Отмена уже принятой сдачи и возврат человеческого управления не предоставляются. | Принято |

## Нефункциональные требования

| ID | Требование | Статус |
| --- | --- | --- |
| NFR-001 | В штатном окружении бот должен начать обслуживать место не позднее 5 секунд после подтвержденной сдачи. | Принято |
| NFR-002 | После рестарта восстановление сдавшихся ботов должно завершаться до первого нового player-facing обязательного prompt и не позднее 10 секунд после готовности сервера. | Принято |
| NFR-003 | Все focused route, flow, persistence, ELO и client regressions должны проходить без флаков в трех последовательных локальных запусках. | Принято |
| NFR-004 | Staging smoke должен пройти без browser console errors и без зависшего обязательного prompt после Surrender. | Принято |

## Ограничения

| ID | Ограничение | Статус |
| --- | --- | --- |
| C-001 | Автоматическое определение Abandoned по бездействию, таймауту или закрытой вкладке не входит в scope. | Принято |
| C-002 | Текущая игра `g9e9c7f0b6fff` и ее ELO/БД не изменяются этой code mission. | Принято |
| C-003 | Для `g9e9c7f0b6fff` согласован отдельный будущий ops-result: `Nuke = 1`, `vvbMinsk = 2 (surrendered)`, `Борис = 3 (abandoned)`; применение требует отдельного live/DB разрешения. | Принято |
| C-004 | Surrendered human не добавляется в `botPlayerIds`, иначе вся партия ошибочно выпадет из ELO как изначально bot game. | Принято |
| C-005 | Prod deploy, prod restart, ручной bot start и рейтинг-пересчет являются отдельными gates. | Принято |

## Критерии успеха

- Во всех покрытых фазах после Surrender партия продолжает работу без действий
  человека за сдавшееся место.
- Сценарий Surrender перед WGT завершается действиями бота и не зависает.
- После restore/restart сдавшийся бот возвращается автоматически.
- В ELO fixture с `completed`, `surrendered` и `abandoned` получаются места
  1, 2 и 3 соответственно, а leave-счетчик увеличивается только для
  `abandoned`.
- Никакое действие baseline или реализации не меняет `g9e9c7f0b6fff`, prod БД
  или live runtime без отдельного разрешения.

## Предположения

- Подтверждение Abandoned выполняется отдельным ручным/операционным решением;
  автоматический detector будет отдельной задачей, если понадобится.
- Для нескольких игроков одной outcome group остаются штатные VP/MC tie-breakers.
- UI-термин `Surrender` сохраняется; `Abandoned` является результатом, а не
  новой player-facing кнопкой в этой mission.

## Вне scope

- Автоматический inactivity detector.
- Кнопка возврата управления человеку.
- Новая admin UI для разметки Abandoned.
- Изменение стратегии SmartBot.
- Мутация текущей партии, ручной пересчет ELO и prod deploy.
