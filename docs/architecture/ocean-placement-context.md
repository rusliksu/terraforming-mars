# Факты размещения океана для оценки текущего поколения

## Бонусный океан от температуры: только TR

Согласовано 2026-10-14: два PR, сервер и advisor, без deploy и установки.
База сервера — `df0f3825cc19744493ad95d6249eec0e429e6f7f`.
Необязательное `temperatureBonus` внутри прежнего `oceanPlacementContext/version1`
содержит текущую температуру, её предел и три котировки `{steps, oceans}` для
изолированного подъёма на 1/2/3 шага. Пороги берутся из конфигурации этой игры,
не из знания клиента про 0°C. Число океанов ограничено остатком океанического
трека; два градуса на шаг соответствуют действующему `Game.increaseTemperature`.

Это числовые факты собственного action-контекста, не доказательство оплаты,
полного исполнения карты или доступности размещения. Модель не исполняет
эффекты, не клонирует игру и не меняет сериализованное состояние. Сохранённая
схема и БД не затронуты. Существующие одиночные клетки и пары не меняются.
Advisor применяет эти котировки только к source-certified эффекту температуры
без собственных океанов: считает только TR через общего владельца оценки,
без клеток, соседства, других пороговых наград и цепочек. Оценка остаётся частичной.

Проверено в этом пакете: `build:test`, client `vue-tsc --noEmit`, ESLint трёх
затронутых TS-файлов, девять context-тестов и два source/catalog-теста.
Котировка с −4°C на два шага совпала с фактическими 3 TR после размещения;
перенесённые пороги и остаток 2/1/0 океанов проверены отдельно. Source guard
обновлён только для двух изменённых модулей, без смены catalog identity.
Настоящий PlayerModel через JSON передан в Chromium worker/main на 1280/390 px:
бонус, нулевая котировка, старый сервер, stale context и cap дают ожидаемый Now
при неизменном Base и без page/console errors. Живые игры не использовались.

Структурная самопроверка: `APPROVE WITH RISKS`, блокирующих замечаний нет.
Триггеры, доступность и стоимость последующего размещения не сертифицированы;
это намеренная граница частичного TR-расчёта, не gameplay admission.
Полный server/client suite локально в этом пакете не повторялся. Локальный Node
24.19.0 отличается от cloud Node 22; CI и решение о merge отслеживаются в PR.

## Два последовательных океана

Согласовано 2026-10-14: отдельные PR сервера и advisor, без deploy и установки.
База сервера — `923ba2f3a0e811975c0e1049d1be30e000a16782`.
Необязательное поле `pairs` расширяет прежний `version: 1`, не меняя одиночные
котировки. Каждая запись содержит `firstSpaceId`, `secondSpaceId` и готовый
`secondOceanAdjacencyBonus`. Обе клетки берутся из прежних `spaces`; их печатные
бонусы и затраты сохраняются. Первую клетку повторно использовать нельзя.

Соседство и коэффициент остаются у сервера. Установка тайла, клонирование игры,
выполнение карт, DB и сохранённая схема не нужны. Размещения не меняют обычный
список оставшихся океанических клеток; действующие overrides применены до
построения пар. Если остаётся менее двух океанов, поле отсутствует. Пары также
не подтверждаются при неподдержанном политическом сборе, более 64 кандидатах
или ещё доступных Ares-событиях изменения поля по числу океанов.

Общий brain проверяет оплату карты, затем каждого размещения из одного остатка:
сбор и TR-налог оплачиваются до соответствующего бонуса. Только фактические
денежные бонусы первого размещения могут финансировать второе; сталь, добор,
производство и ещё не полученный второй бонус не заменяют деньги. Неизвестные
триггеры и неподдержанные бонусы остаются частичными. Это не gameplay admission.

## Предыдущий одиночный пакет

Сервер сообщает собственному игроку варианты стандартного размещения океана на
текущем поле. Он не выбирает клетку, не оценивает карты и не выполняет действия.
Общий brain переводит подтверждённые бонусы и дополнительные затраты в пользу
текущего поколения. Доставка — через отдельные PR сервера и advisor, без deploy.

Новый необязательный `thisPlayer.oceanPlacementContext` с `version: 1` содержит
цвет игрока, поколение, номер сохранения, текущее число и предел океанов, а также
структурно доступные клетки: id, печатные бонусы, денежный бонус соседних океанов
и дополнительные затраты размещения. Доступность клетки не доказывает оплату
карты или последующих сборов: бюджет после оплаты проверяет потребитель.

## Владельцы правил

- `MarsBoard.getAvailableSpacesForOcean` и overrides определяют клетки.
- `Board.getAdjacentSpaces` и `Board.isOceanSpace` определяют соседство;
  `player.oceanBonus` задаёт действующий коэффициент.
- Общий запрос дополнительных затрат используется и `Board.canAfford`, и моделью.
- Выбор обязательного политического сбора общий для выполнения и модели.
  Неподдержанный сбор явно запрещает числовую оценку бонуса этой клетки.
- `Server.getPlayer` добавляет контекст только самому игроку в фазе действий;
  spectator и чужие публичные модели его не получают.

Контекст не описывает срабатывания карт, политические награды, Ares-награды
соседства, подземные бонусы или последовательность нескольких размещений. Это
не доказательство полного эффекта карты и не разрешение хода. Клиент первой
версии оценивает один стандартный океан, обычные ресурсные бонусы и добор;
неизвестные/устаревшие данные и специальные бонусы остаются частичными.
