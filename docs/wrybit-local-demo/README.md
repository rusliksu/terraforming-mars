# Локальное демо Wrybit UI

Это окружение запускает собранный клиент и сервер локально на SQLite, чтобы проверять Wrybit-интерфейс без production-базы и без внешних сервисов.

## Требования

- Node.js 22+
- npm
- свободный порт `8081`

## Первый запуск

Из корня репозитория:

```bash
npm ci
npm run build
npm run make:css
```

Запуск сервера:

```bash
PORT=8081 HOST=127.0.0.1 npm start
```

В PowerShell:

```powershell
$env:PORT='8081'
$env:HOST='127.0.0.1'
npm start
```

Открыть: [http://127.0.0.1:8081/](http://127.0.0.1:8081/).

Wrybit включается переключателем **Wrybit layout** в правом верхнем углу классического экрана. Обратный переключатель **Classic layout** возвращает обычный интерфейс. Настройка хранится в браузере.

## Данные

По умолчанию используется SQLite-база `db/game.db`. Она сохраняется между перезапусками. Для чистой демонстрации можно сделать резервную копию файла и удалить его только при остановленном сервере.

В логе запуска печатаются служебные идентификаторы и адрес административных маршрутов. Не публикуй эти идентификаторы и не используй production-базу для локальных проверок.

## Разработка

Для горячей перезагрузки удобнее:

```bash
npm run dev
```

После изменений клиента в собранном режиме:

```bash
npm run build:client
npm run make:css
```

Сервер нужно перезапускать после изменений серверного кода. Клиентские файлы подхватываются после обновления страницы.

## Проверки

```bash
npm run test:client
npm run lint
```

## Горячие клавиши

- `?` — помощь по клавишам;
- `Q`, `W`, `E` … — вкладки действий;
- `1–99` — выбор карточек; при большом количестве вариантов код написан на самой карточке;
- стрелки — перемещение по карточкам, `Enter` — выбор подсвеченной карточки;
- `Enter` — подтверждение, `Esc` — отмена/закрытие.

## Если порт занят

Проверить процесс можно так:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8081
```

Остановить старый демо-сервер и запустить снова. Не запускай второй экземпляр на том же порту.
