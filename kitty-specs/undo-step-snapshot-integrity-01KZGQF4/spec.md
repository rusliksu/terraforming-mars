# Спецификация: целостность снапшота step undo

## Цель

Экспериментальная команда «назад на один шаг» должна восстанавливать состояние до отменяемого ввода без повторного применения уже выполненных изменений. Корневой снапшот журнала replay обязан быть независим от последующих мутаций живой игры.

## Подтверждённый инцидент

В партии `ga3f7a84cf0e1` карта Giant Ice Asteroid была отправлена один раз. После двух step-back и повторного выбора второго океана поле осталось с корректными девятью океанами, однако сумма вкладов игроков стала равна одиннадцати; аналогично вклад в температуру превысил фактическое число шагов на два. Причина — `ActionReplay` сохранил shallow serialized state, чьи вложенные объекты продолжили изменяться вместе с живой игрой.

## Пользовательские сценарии

### US-001 — Откат многошагового глобального эффекта

Игрок разыгрывает Giant Ice Asteroid, выбирает два океана и цель удаления растений, затем возвращается на один или несколько шагов и выбирает другой допустимый ответ. После replay каждый фактически сохранённый эффект учитывается ровно один раз.

### US-002 — Откат изменяемого вложенного состояния

Если шаг меняет журнал, данные дополнения, данные карты либо метаданные тайла, отменённое изменение не остаётся в корневом снапшоте и не появляется повторно после replay.

### US-003 — Сохранение защит существующего step undo

Детерминированный replay, объединённые логические шаги и блокировка отката после раскрытия скрытой информации продолжают работать без изменения пользовательского контракта.

## Функциональные требования

| ID | Требование |
| --- | --- |
| FR-001 | `ActionReplay` сохраняет корневой `SerializedGame` как полностью отделённый JSON-снапшот, который не меняется при последующих мутациях живой игры. |
| FR-002 | После step-back и replay Giant Ice Asteroid два океана и два шага температуры учитываются в `globalParameterSteps` ровно один раз, а число океанов на поле соответствует фактическим размещениям. |
| FR-003 | Сообщения `gameLog`, отменённые шаги и их `canceled`-метки не дублируются из-за загрязнённого root snapshot. |
| FR-004 | Та же граница снапшота защищает все сериализованные вложенные структуры, включая expansion/card/tile state, без перечисления и исправления отдельных сериализаторов. |
| FR-005 | Existing deterministic replay и hidden-information guards сохраняют прежнее поведение. |
| FR-006 | Архитектурная документация явно фиксирует invariant неизменяемого root snapshot. |

## Нефункциональные требования

| ID | Требование |
| --- | --- |
| NFR-001 | Исправление локализовано в границе захвата `ActionReplay`; глобальная семантика `Game.serialize()` не меняется. |
| NFR-002 | Для копирования используется тот же JSON-compatible контракт, который уже применяется перед `Game.deserialize()` при replay; новые runtime-зависимости не добавляются. |
| NFR-003 | Производительность остаётся пропорциональной одному дополнительному JSON round-trip на создание root journal, а не на каждый сериализатор или поле. |
| NFR-004 | Изменение покрывается regression-first тестами и проходит релевантные server lint/build/test gates. |

## Вне скоупа

- Изменение обычного полного undo/reset через сохранённые игры.
- Изменение правил Giant Ice Asteroid или глобальных параметров.
- Переписывание всех `serialize()` методов на deep clone.
- Ослабление hidden-information либо deterministic-replay проверок.
- Миграция уже завершённых партий или пересчёт их исторической статистики.
- Live/prod deploy без отдельного явного разрешения.

## Критерии приёмки

- Тест сначала воспроизводит изменение root snapshot после мутаций live game и падает на исходном коде.
- После исправления root snapshot не меняется для `gameLog`, `globalParameterSteps` и репрезентативного вложенного mutable state.
- Поведенческий Giant Ice Asteroid сценарий подтверждает отсутствие двойного вклада после двух step-back.
- Все существующие `ActionReplay.spec.ts` сценарии остаются зелёными.
- Targeted server tests, server lint/type/build checks и `git diff --check` проходят.
- Изменение доставляется task-owned PR в `main`; staging и prod остаются отдельными delivery gates.
