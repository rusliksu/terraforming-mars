# Реплей завершённой партии

Кнопка «Реплей партии» на странице результатов и завершённой странице зрителя
открывает `/replay?id=<spectatorId>`. Доступ определяется ссылкой зрителя.
Страница показывает первое доступное сохранение и начинает с паузы.

Доступны воспроизведение, пауза, шаги назад и вперёд, начало, конец, ползунок
и скорости 0.5×/1×/2×/4×. Интервал 1× — одна секунда после загрузки кадра.
Ручной выбор ставит воспроизведение на паузу; последний кадр останавливает его.
Кнопки и ползунок работают с клавиатуры. Большое поле, колонии и обзор игроков можно
прокручивать внутри их блоков на узком экране.

Поле — главный элемент экрана: от 1200 px ширины окна оно показывается в масштабе 1.3,
от 1700 px — 1.5; без поддержки CSS-свойства масштабирования остаётся натуральный размер,
а блок по-прежнему прокручивается. Ссылка «Вернуться к партии» остаётся обычной ссылкой
с всплывающей подсказкой: видимых плашек-инструкций на странице нет.

Позиция — номер среди реально записанных сохранений. Она не является номером
действия и не подтверждает, что история содержит каждое действие партии.
Команды заново не исполняются. Поле, публичные ресурсы, производство, сыгранные
карты и журнал относятся к выбранному сохранению; приватные руки и драфт
не раскрываются, в том числе на последнем кадре.

## Контракт и границы

`GET /api/replay?id=<spectatorId>` возвращает имя партии и упорядоченные ID
сохранений. Добавление `&saveId=<id>` возвращает один публичный кадр.
Список ограничен 4096 сохранениями; ID кадра должен быть безопасным целым
неотрицательным числом. Пропущенный ID не заменяется соседним.

API ищет ссылку по журналу участников `IDatabase.getParticipants`, затем
сверяет `spectatorId` и `END` с последним сохранением до и после асинхронного
чтения. Это избегает полного JSON-скана SQLite через `getGameId`.
Заново открытая партия или заменённая ссылка получают отказ. Ответы имеют
`Cache-Control: no-store`. Предел сервера — четыре параллельных запроса без
очереди; лишний запрос получает 429 и `Retry-After: 1`.

Просмотр использует обычные `getSaveIds/getGameVersion`, поэтому доступны
как строки БД, так и привязанный [приватный архив](game-history-archive.md).
Один кадр ограничен 8 MiB до проекции; действуют также лимиты архивного читателя.
Сырые сохранения, пути и архивные файлы через этот API не выдаются.
Браузер держит один активный запрос и до восьми кадров. Новый выбор отменяет
предыдущий запрос; устаревший ответ или ошибка не меняют текущий выбор.

`Game.deserialize(..., {viewOnly: true})` создаёт отдельное представление,
не продолжая фазу и не восстанавливая общие часы живых игр. Проекция явно
выбирает публичные поля и сообщения. Страница не монтирует `WaitingFor`
и живой `LogPanel`; общий обзор игроков получает `readOnly`, отключающий
текущий рейтинг и живые таймеры. Просмотр не сохраняет и не откатывает партию.

При недоступном кадре поле очищается, воспроизведение останавливается и
появляется сообщение с повторной загрузкой. Есть ссылка возврата к партии.
Пока загружается следующий кадр, предыдущий остаётся на экране; поле и обзор
игроков обновляются вместе после получения ответа, без промежуточного исчезновения.
Повреждение или отсутствие архива не маскируется успешным пустым ответом.

## Воспроизводимая локальная проверка

Генератор создаёт только новую собственную SQLite под существующим
`D:/tm-db/smartbot-lab`. Он отказывает для других разрешённых системой путей,
не открывает существующие базы и ограничен двумя партиями: 4 и 100 состояний.
Короткая история содержит ID 0, 4, 9, 12 и фазы драфта, исследования,
производства и завершения. Рядом записываются независимые ожидаемые значения
и синтетические приватные маркеры в `fixture.json`.

Из проверяемого checkout:

```powershell
npm run build
$source = (Get-Location).Path
$lab = 'D:/tm-db/smartbot-lab/replay-check'
New-Item -ItemType Directory -Path $lab -Force | Out-Null
$env:TM_DISABLE_TELEGRAM = '1'
$env:ELO_DATA_DIR = Join-Path $lab 'elo'
$created = @(node --import=tsx scripts/replay/create-fixture.ts $lab)
$fixture = $created[-1] | ConvertFrom-Json
New-Item -ItemType Junction -Path (Join-Path $fixture.workspace 'build') -Target (Join-Path $source 'build')
New-Item -ItemType Junction -Path (Join-Path $fixture.workspace 'assets') -Target (Join-Path $source 'assets')
Set-Location -LiteralPath $fixture.workspace
$env:HOST = '127.0.0.1'
$env:PORT = '18091'
$env:SERVER_ID = 'replay-fixture-admin'
$env:NODE_ENV = 'production'
$env:TM_HISTORY_ARCHIVE_ROOT = $fixture.archiveRoot
$env:TM_HISTORY_ARCHIVE_WORKSPACE = $fixture.workspace
node build/src/server/server.js
```

Сервер должен сообщить именно созданную D:-базу. Выбрать свободный порт;
не останавливать чужой процесс. После пересборки клиента перезапустить только
этот сервер: production-кеш ресурсов хранит уже прочитанные JS-файлы.

Playwright CLI запускать из D:-каталога **с первого `open`**: каталог вывода
закрепляется за браузерной сессией. Для полного входа открыть
`/the-end?id=spectator-id-replay-ui` и нажать «Game replay».
Локальный Node-сервер не обслуживает статический `/elo/*.json`, который обычно
отдаёт внешний веб-сервер. Только для страницы результатов допустима отдельная
статическая fixture `{"players":{},"games":[]}`; API игры и реплея не подменяется.

```powershell
npx --yes --package '@playwright/cli' playwright-cli -s=replay-check open http://127.0.0.1:18091/replay?id=spectator-id-replay-ui
npx --yes --package '@playwright/cli' playwright-cli -s=replay-check run-code --filename (Join-Path $source 'scripts/replay/browser-smoke.js')
npx --yes --package '@playwright/cli' playwright-cli -s=replay-check run-code --filename (Join-Path $source 'scripts/replay/browser-performance.js')
```

Первый сценарий проверяет реальные кадры, карточную панель, паузу, управление,
клавиатуру, приватность и отсутствие посторонних API-запросов. Второй выполняет
20 некешированных переходов на истории из 100 состояний, включая два кадра
отрисовки браузера в измерение; проверяет p95 < 2 секунд и один активный запрос.

Перед архивированием остановить только собственный тестовый сервер.
Использовать штатный [оператор архива](sqlite-history-retention.md) с явными
`--offline --database <fixture.filename> --archives <fixture.archiveRoot>
--workspace <fixture.workspace> --game game-id-replay-ui --max-states 4`.
После проверки preview применить ровно его revision с `--apply --exclusive`.
Для второй партии — `game-id-replay-perf` и бюджет 100. Повторить браузерные
сценарии после запуска того же сервера и сравнить публичные кадры и хеши файлов.
Намеренные повреждения допустимы только в этой синтетической fixture;
восстановление должно вернуть исходные байты.
