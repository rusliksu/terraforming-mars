## Почему

Работающий сервер создаёт и удерживает деревья `renderData` для карт и глобальных событий, хотя эти данные использует только сборочный экспортёр клиентского `cards.json`. Адаптация уже принятого upstream-изменения `#8337` уберёт лишнюю работу при старте и ненужное удержание памяти без изменения игрового поведения.

## Что изменится

- Серверный процесс будет явно помечаться как live runtime до создания экземпляров карт и глобальных событий.
- `CardRenderer.builder` в live runtime будет возвращать общий пустой корень и не выполнять callback построения метаданных.
- Сборочные инструменты и тесты, которые не помечены как live runtime, продолжат создавать полные `renderData`.
- Объявления `renderData` глобальных событий и затронутых community/pathfinders/underworld-карт будут перенесены из module scope в конструкторы, чтобы live-маркер применялся до построения.
- Игровые правила, API, сохранения, БД и клиентский вид карт не изменятся.

## Возможности

### Новые возможности

- `live-server-card-render-metadata`: управление построением метаданных отображения карт в зависимости от типа процесса.

### Изменённые возможности

- Нет.

## Влияние

- Код: `src/server/cards/render/CardRenderer.ts`, `src/server/server.ts`, `src/server/utils/server.ts` и определения `renderData`, входящие в upstream PR `#8337`.
- API и данные: без изменений внешних контрактов, схем сохранения и БД.
- Зависимости: новые зависимости и настройки окружения не добавляются.
- Доставка: отдельный task-owned PR в `rusliksu/terraforming-mars`; после проверок допустим staging, prod остаётся отдельным явным gate.
