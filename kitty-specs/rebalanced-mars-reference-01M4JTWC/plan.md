# План переноса Rebalanced

Основа и ветка реализации: `codex/rebalanced-mars-reference`. Публичная интеграция — отдельный PR в `rusliksu/terraforming-mars`, целевая ветка `main`. Дата: 2026-10-10. Требования — [spec.md](spec.md).

## Решение

Добавить самостоятельный модуль Rebalanced через существующие настройки и манифесты. Перенести ровно 113 активных замен публичного rebalakefak. Использовать текущие базовые классы и игровые hooks; не переносить старый движок fork. Пять пересечений получают отдельные итоговые варианты, два проекта сохраняют Better Mars целиком по прямому решению Руслана.

## Technical Context

Имена следующих двух полей являются техническим форматом обязательной проверки плана.

**Language/Version**: TypeScript 6.0.3, Node.js 22.x, Vue 3.4.
**Primary Dependencies**: существующие Card, ModuleManifest, GameCards, Behavior, Mocha 12, Vitest 4; новые зависимости не нужны.

Разработка — Windows; runtime и staging — Linux. Формат сохранения игры расширяется выключенным по умолчанию флагом; миграция БД не требуется. Проверки: профильные Mocha/Vitest, сборка тестов, lint, полная сборка, CI, API и Playwright на staging.

## Соответствие правилам проекта

Изменения выполняются в собственном изолированном каталоге и ветке. Primary main остаётся зеркалом remote. Профильные тесты сначала воспроизводят недостающие правила, затем проверяются после реализации; итоговый diff проходит focused review. Staging разворачивается только из чистого штатного release checkout, точно равного origin/main. Продакшен требует отдельной команды и proof path. Секреты и данные действующих игр не изменяются.

## Источники и независимая проверка

- `reference-inventory.json` — 113 активных фабрик из опубликованного bundle rebalakefak, версия 28846e8; файл содержит SHA-256 bundle.
- Читаемый источник — pe5ha/pe5ha-mars, ветка heroku, commit ac3b05abd3bb26a9fa98dca8c2700e2475fa92a9. Его 109 активных карт входят в референс; поведения сверяются отдельно.
- Четыре дополнительные карты референса: Asteroid Mining Consortium, Energy Tapping, Hackers, Sabotage; их требования и действия извлечены из публичного кода.
- alrusdi содержит старый набор 47 карт. Современный fork wjcxymy поддерживает Prelude 2, но его Rebalanced меняет только 18 корпораций; его авторские изменения не входят в согласованный набор.
- Часть старых эффектов находится в Game/Player. Проверить все call sites перед переносом и использовать нынешние hooks, а не проверки конкретного нового имени в общем движке.

## Границы и потоки

`NewGameConfig.expansions.rebalanced` передаётся в `GameOptions.rebalancedExpansion` и существующее поле expansions. Оба create-game маршрута, ServerModel, сохранение/загрузка и повторные настройки используют один выбор. Отсутствующее старое поле означает false.

RebalancedCardManifest регистрирует проекты, корпорации, прологи и стандартный проект. Совместимость учитывается перед фильтрацией замен. Общий filterReplacedCards используется сервером и клиентом; экспорт манифестов остаётся источником правил клиента. Замена оригинала удаляется только при наличии совместимой итоговой карты.

Для семи пересечений: пять итоговых фабрик требуют оба модуля и соответствующие зависимости; Mars University и Meat Industry исключают Rebalanced-версию при доступном Better Mars. Выключенная зависимость возвращает доступную одиночную версию. При новом Rebalanced необходимо отдельно проверить ручные includedCards и старые шаблоны; существующие правила override без нового флага сохраняются.

## Порядок реализации

1. Сформировать независимый oracle и классифицировать отличия 113 карт от текущих оригиналов; проверить старые эффекты вне классов карт.
2. Перенести 21 пролог и стандартный проект с тестами ресурсов, производства и размещения.
3. Перенести 32 корпорации с тестами стартового состояния, hooks, действий, влияния и очков.
4. Перенести 59 проектов группами; отдельно проверить требования поколения, атаки, защиту ресурсов и отложенные действия.
5. Подключить манифест, пять комбинаций, приоритет двух Better Mars и общую фильтрацию.
6. Подключить настройки, интерфейс и сохранения; проверить создание, начальную раздачу, старые шаблоны и загрузку.
7. Обновить необходимые source fingerprints, выполнить проверку качества, PR/CI и staging. Условия продакшена остаются отдельными.

## Проверки приёмки

Ожидаемые значения берутся из публичного референса, не из новой реализации. Проверяются все цены и теги, а игровые тесты закрепляют изменённые эффекты. Для семи пересечений проверяется матрица выключенных/включённых модулей и нужных зависимостей. Mutation check должен обнаружить потерю дополнительных ресурсов Early Settlement и неверный приоритет Better Mars. Загрузка сохраняет варианты и эффекты. Реальный API создаёт партию с прежним ручным списком без дубля; Playwright проверяет настройки и начальный выбор без ошибок консоли. Во время staging prod/current, manifest и время запуска prod-сервиса остаются неизменны.

## Риски

Старые именные проверки в Game/Player могут скрывать эффекты наследуемой карты. Числовые отличия метаданных не гарантируют совпадение действий. Порядок отложенных действий, влияние и защита ресурсов проверяются независимо. Неактивные карты из enum и чужие дополнения не регистрируются. Если новый source fingerprint затрагивает неожиданный файл, остановить генерацию и проверить причину.
